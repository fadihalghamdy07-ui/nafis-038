# نافس 038 | نحو القمة

تطوير على ملفات المنصة الحالية بهوية كحلية وذهبية. الواجهة ثابتة على GitHub Pages، وتُرسل طلبات الحفظ إلى Neon Function؛ لا يتصل المتصفح بقاعدة البيانات مباشرة.

## الملفات

- `index.html`: بوابة الطالبات، مغلقة افتراضيًا.
- `admin.html`: لوحة الإدارة وتضم المميزات العشر، مع إدخال يدوي واستيراد ملف/رابط وأرشفة النتائج ونشر الاختبارات.
- `functions/nafis-api.mjs`: نقطة تشغيل Neon Function وتهيئة مجمع اتصال `pg` من `DATABASE_URL` الذي تحقنه Neon.
- `functions/nafis-api-core.mjs`: الدخول، المصادقة، حفظ المحاولات ومنع تكرارها، ونشر النتائج المجدول.
- `database/nafis038_setup.sql`: تهيئة غير هدامة للجداول الحالية، وإضافة جدول المسودات وقيد المحاولة الفريد.
- `api-config.example.js`: مثال رابط API العام فقط؛ لا يحتوي أسرارًا.

## تجهيز Neon

1. في Neon SQL Editor، شغّلي `database/nafis038_setup.sql` باستخدام دور قاعدة البيانات نفسه الذي ستستخدمه Neon Function. يحافظ الترحيل على الجداول والبيانات، ويضيف جدول حفظ المسودات وقيدًا فريدًا يمنع المحاولة المكررة، ويثبت RLS وFORCE RLS وسياسة وصول لدور الوظيفة فقط. إذا ظهرت رسالة عن محاولات مكررة، راجعي السجلات أولًا؛ لن يحذف الترحيل أي محاولة تلقائيًا.
2. من جذر هذا المشروع ثبتي الحزم: `npm install`، ثم ثبتي Neon CLI (`npm install -g neon@latest`) واربطِي المجلد بقاعدة بياناتك: `neon link`.
3. أضيفي هذه القيم إلى `.env.local` (وهو مستثنى من Git) قبل النشر. لا تضعيها في GitHub Pages:
   - `NAFIS_ADMIN_EMAIL`: بريد حساب الإدارة.
   - `NAFIS_ADMIN_PASSWORD_HASH`: قيمة scrypt الناتجة عن أداة التجزئة.
   - `NAFIS_SESSION_SECRET`: قيمة عشوائية طويلة لا تقل عن 32 بايت.
   - `NAFIS_ALLOWED_ORIGINS`: `https://fadihalghamdy07-ui.github.io` مع أي أصل محلي تحتاجينه أثناء التطوير.
   - `NAFIS_STUDENT_PORTAL_ENABLED`: اتركيها `false` حتى اكتمال الفحص والمراجعة.
4. أنشئي تجزئة كلمة المرور محليًا بواسطة `npm run hash-password -- "كلمة-مرور-طويلة-وفريدة"` وانسخي الناتج إلى `.env.local` باسم `NAFIS_ADMIN_PASSWORD_HASH`. لا تضعي كلمة المرور أو التجزئة أو `DATABASE_URL` في ملف متتبع.
5. انشري وظيفة Neon باستخدام `neon deploy --env .env.local`، ثم خذي عنوانها من `neon functions get nafisapi`. ينشئ `neon.ts` مشغل النتائج كل سبت عند `15:00 UTC`، أي `18:00` بتوقيت السعودية، عبر مسار داخلي لا يقبل إلا استدعاء Neon المجدول. جداول النتائج تصبح متاحة بعد تشغيله فقط.
6. انسخي عنوان الوظيفة إلى نسخة من `api-config.example.js` باسم `api-config.js` في ملفات GitHub Pages. عنوان API وحده عام بطبيعته؛ لا تضعي فيه بيانات اتصال Neon أو بيانات الإدارة.
7. لا تفتحي بوابة الطالبات حتى ينجح فحص `/health` و`/admin/health` وحفظ محاولة اختبار ومنع تكرارها. الفتح يتطلب أيضًا `students_enabled=true` في صف الإعدادات ومتغير Neon `NAFIS_STUDENT_PORTAL_ENABLED=true`.

## بديل آمن إذا تعذر نشر Neon Function: Vercel

الملفات `api/[...path].mjs` و`api/cron/publish-results.mjs` و`vercel.json` تشغّل نفس منطق API على Vercel وتبقي `DATABASE_URL` وأسرار الإدارة في بيئة الخادم. مسار الجدولة محمي بـ `CRON_SECRET` ولا يمر عبر مسار API العام. يعمل الموعد السبت 15:00 UTC (6 مساءً بتوقيت السعودية).

1. ارفعي مجلد المشروع إلى مستودع GitHub خاص، ثم اختاريه في Vercel عبر **Add New → Project → Import**.
2. في **Project → Settings → Environment Variables** أضيفي القيم التالية لبيئة Production: `DATABASE_URL` (سر Neon)، `NAFIS_ADMIN_EMAIL`، `NAFIS_ADMIN_PASSWORD_HASH`، `NAFIS_SESSION_SECRET` (عشوائي طويل)، `NAFIS_ALLOWED_ORIGINS=https://fadihalghamdy07-ui.github.io`، `NAFIS_STUDENT_PORTAL_ENABLED=false`، و`CRON_SECRET` (سر عشوائي مستقل). لا تضعي أيًا منها في ملفات الواجهة أو GitHub.
3. أعيدي النشر من Vercel. عنوان الواجهة الخلفية في `api-config.js` يكون `https://عنوان-المشروع.vercel.app/api` فقط. اختبري `/health` ثم سجّلي الدخول واختبري `/admin/health` وإضافة سؤال تجريبي ومحاولة محفوظة وعدم تكرارها. لا تفتحي بوابة الطالبات.
4. لاختبار إعلان السبت قبل تشغيل الطالبات، استخدمي نسخة/بيانات اختبارية مخصصة؛ لا تشغّلي مسار الجدولة على النتائج الحقيقية يدويًا. راقبي تنفيذ Cron من Vercel بعد أول موعد، ثم أعيدي فحوص الحماية.

هذه الحزمة تجهز ملفات الاستضافة فقط؛ لا تعني أن Vercel أو Neon Function قد نُشرت، ولا أن API حية اختُبرت. بعد النشر الحي يجب نجاح الفحوص أعلاه قبل أي فتح للبوابة.

## التشغيل والفحوص

- `npm test`: اختبارات حماية الدخول، إغلاق البوابة، CORS، النشر في الموعد المحدد، وعدم كشف مفاتيح الإجابات.
- `node --check "api/[...path].mjs"` و`node --check api/cron/publish-results.mjs`: فحص محولات Vercel.
- `node --check functions/nafis-api-core.mjs` و`node --check functions/nafis-api.mjs`: فحص صياغة JavaScript.
- `/admin/health` يعرض تفعيل RLS وFORCE RLS وسياسة الدور لكل جدول. عالجي أي جدول غير جاهز قبل إدخال بيانات حقيقية.

الاختبارات المحلية لا تستبدل اختبار تكامل حي مع Neon. لا يمكن نشر الوظيفة أو التحقق من الاتصال الحي دون ربط المشروع وبيانات دخول Neon في بيئة النشر.

## ما تحميه الواجهة الخلفية

- تحفظ إجابات الطالبة تدريجيًا في جدول مسودات Neon، وتستعيدها عند استكمال الجلسة. عند انتهاء المؤقت يحفظ الخادم الإجابات الموجودة ويحتسب غير المجاب عنه خطأً.
- تحفظ المحاولات ومفاتيح الإجابة في Neon، ولا ترسل مفتاح الإجابة أو الشرح إلى الطالبة.
- تحسب الدرجة في الخادم، وتفرض محاولة واحدة عبر القيد الفريد `UNIQUE(exam_id, student_id)`.
- تصدر جلسة اختبار موقعة ومحدودة الوقت، وجلسة إدارة قصيرة العمر بعد التحقق من كلمة مرور مجزأة.
- تُنشر درجات الاختبارات وترتيب المتصدرات تلقائيًا كل سبت الساعة السادسة مساءً بتوقيت السعودية دون اعتماد يدوي. لا تتضمن واجهة النتائج إجابات الطالبات أو مفاتيح التصحيح.
- الاسم والصف والفصل يحدون التكرار فقط ولا يثبتون هوية الطالبة؛ يلزم اعتماد المدرسة لهذه الطريقة قبل فتح الاستخدام من المنزل.
